# 배율 페이스 계산기

보스 배율(20분 동안 뽑아야 할 이상적인 딜량 %) 대비 **내 컨트롤이 몇 퍼센트인지**,
그리고 그 컨트롤로 **어느 배율까지 20분 컷이 되는지** 계산합니다.

👉 https://yh-yeop.github.io/BossPaceCalcul/

## 기능
- 클리어 타임 또는 20분 종료 시 남은 hp로 배율 대비 컨트롤(%)과 20분 컷 최소 배율 계산
- **딜 불가 시간 보정** (선택): 무적·컷신 등 딜을 못 넣은 시간을 빼고 실제 딜 가능 시간 기준으로 컨트롤 계산. 보정이 들어가면 결과에 "딜 불가 N분 제외" 표시
- 목표 계산
  - **다른 배율이면?** 기준 컨트롤로 다른 배율 보스의 예상 클리어 타임 / 남은 hp
  - **목표 시간** 원하는 클리어 타임에 필요한 컨트롤과 최소 배율
- 이 컨트롤이면 체감 배율은?: 배율 단계별로 `배율 × 컨트롤` 체감 배율과 예상 결과 표 (내 기록 배율, 20분 컷 경계 포함)
- **파티로 가면?**: 파티원(2~6명) 배율을 더한 합산 배율로 예상 클리어 타임 / 남은 hp, 각자의 기여 비율, 20분 컷에 더 필요한 배율, 파티 필요 컨트롤
- 기록 히스토리: **기록 저장**을 누르면 보스·배율·결과·컨트롤이 브라우저에 쌓이고, 컨트롤 추이 그래프와 목록에서 다시 불러올 수 있음
  - 보스별 필터와 선택한 보스의 최고·최근 컨트롤 요약
  - JSON 내보내기/가져오기(`boss-pace-records.json`) — 브라우저를 바꿔도 기록을 옮길 수 있음(같은 시각 기록은 중복 제거)
- 보스 이름 자동완성(기본 보스 목록 + 기록에 있는 이름)
- 공유 링크(쿼리 파라미터), 결과 카드 이미지 저장(기록이 2개 이상이면 추이 그래프 포함), 입력값 자동 저장
- 라이트/다크 테마: 기본은 시스템 설정, 헤더 버튼으로 전환
- 오프라인 캐시(Service Worker): 한 번 열면 인터넷 없이도 동작

## 공식
- 이상 속도 = `배율 ÷ 20` %/분, 실제 속도 = `진행% ÷ (걸린 분 − 딜 불가 분)`
- 컨트롤 = `실제 ÷ 이상`
- 체감 배율 = `배율 × 컨트롤비율` (100 이상이면 20분 컷)
- 최소 배율(T분 컷) = `2000 ÷ (컨트롤비율 × (T − 딜 불가 분))` — 딜 불가 0, T = 20이면 `100 ÷ 컨트롤비율`
- 예상 시간 = `2000 ÷ (배율 × 컨트롤비율) + 딜 불가 분` — 20분 컷 판정은 딜 가능 시간 `20 − 딜 불가 분` 안에 뽑는지로 봄
- 파티 합산 배율 = `Σ 파티원 배율` — 배율이 20분 기준 보스 hp 대비 %이므로 단순 합. 기여 비율 = `내 배율 ÷ 합산 배율`
- 20분 컷에 더 필요한 배율 = `max(0, 100 ÷ 컨트롤비율 − 합산 배율)`

전투 내내 같은 페이스를 유지한다는 가정의 참고용 계산입니다. 02·03·파티 계산에는 내 기록에 넣은 딜 불가 시간을 같은 패턴으로 가정해 적용합니다.

## 공유 링크
`?b=보스&r=배율&t=분:초` (잡음) 또는 `?r=배율&hp=남은%` (못 잡음), 딜 불가 시간이 있으면 `&d=분:초`.

## 구성
- `calc.js` 순수 계산 (ES 모듈, DOM 없음) — `test/`에서 그대로 불러와 검사
- `data.js` 보스 이름 기본 목록
- `app.js` 입력·렌더링·저장·공유·파티·기록 히스토리·테마
- `share.js` 결과 카드 캔버스 렌더링
- `sw.js` 오프라인 캐시 — 파일을 바꿔 배포할 때 `VERSION`을 올리면 옛 캐시가 지워집니다

브라우저 저장 키: `bpc:state`(입력값), `bpc:records`(기록), `bpc:party`(파티원), `bpc:theme`(테마).

## 로컬 실행 · 테스트
빌드 과정 없이 정적 파일만으로 동작합니다. ES 모듈을 쓰므로 `file://`이 아닌 로컬 서버로 여세요.
테스트는 의존성 없이 Node 22 이상에서 돌아가고, 푸시마다 GitHub Actions가 같은 테스트를 돌립니다.
```
python -m http.server 5173
npm test
```
